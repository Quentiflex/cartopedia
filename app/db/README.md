# RDF database (Fuseki) — schema & imports

## Folder structure

```
app/db/
├── schema/           # Ontology (TBox)
│   └── ontology.ttl
├── imports/          # Imported RDF data (ABox), e.g. from Wikidata
│   ├── imports.ttl   # Wars + participants + coordinates (generated by scripts)
│   └── wikidata_wars_small.ttl
└── README.md         # This file
```

- **schema/** — Your ontology: classes (`ex:War`, `ex:Event`, …) and properties (`ex:startDate`, `ex:endDate`, `ex:hasParticipant`, `ex:latitude`, `ex:longitude`, …).
- **imports/** — Instance data (wars, participants, coordinates). `imports.ttl` is generated by `scripts/1-fetch-wikidata-wars.js` and includes participant coordinates from Wikidata P625 for mapping.

Fuseki endpoint (Docker): `http://127.0.0.1:3030/history/`  
- Dataset: `http://127.0.0.1:3030/history/data`  
- SPARQL: `http://127.0.0.1:3030/history/sparql`

The app uses `Accept: application/sparql-results+json` so Fuseki returns JSON. Optional env for the Next.js server: `FUSEKI_SPARQL_URL`, `FUSEKI_USER`, `FUSEKI_PASSWORD` (or `FUSEKI_AUTH` base64) if Fuseki requires auth.

## Upload RDF into Fuseki (with auth)

From project root:

```powershell
curl.exe -u admin:admin -X POST `
  -H "Content-Type: text/turtle" `
  --data-binary "@app/db/imports/wikidata_wars_small.ttl" `
  http://127.0.0.1:3030/history/data
```

Success: no output, no error.

## Verify — list all wars (SPARQL)

Request **JSON** so Fuseki does not return XML: use `Accept: application/sparql-results+json`.

```powershell
curl.exe -X POST `
  -H "Content-Type: application/sparql-query" `
  -H "Accept: application/sparql-results+json" `
  --data "
PREFIX ex: <http://example.org/ontology/>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>

SELECT ?war ?label ?start ?end WHERE {
  ?war a ex:War ;
       rdfs:label ?label ;
       ex:startDate ?start .
  OPTIONAL { ?war ex:endDate ?end }
}
ORDER BY ?start
" `
  http://127.0.0.1:3030/history/sparql
```

Expected: JSON with wars (Franco-Prussian War, World War I, World War II, etc.). If Fuseki requires auth, add `-u admin:admin`.

## Mapping: participant coordinates for a war

Participants (countries/states) have `ex:latitude` and `ex:longitude` when available from Wikidata (P625). To get points for the map for a given war:

```sparql
PREFIX ex: <http://example.org/ontology/>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>

SELECT ?participant ?label ?lat ?lon WHERE {
  ?war a ex:War ;
       ex:hasParticipant ?participant .
  ?participant rdfs:label ?label .
  OPTIONAL { ?participant ex:latitude ?lat ; ex:longitude ?lon . }
  # FILTER (?war = ex:wd_Q361)   # e.g. World War I
}
```

Use `?lat` and `?lon` to build GeoJSON points: `{ "type": "Point", "coordinates": [?lon, ?lat] }` (GeoJSON is lon, lat).
